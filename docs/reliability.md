# Надёжность LabFrame — 31 октября 2026

Обычная обработка сохраняет задание и резервирует баланс одной транзакцией.
Ключ запроса защищает повторы. Вызовы генератора сохраняются в `ai_image_attempts`:
после получения номера задачи выполняется polling этой задачи. Неопределённый
результат POST не запускает повторную платную генерацию. Задание ограничено
12 минутами; клиент ждёт до 14 минут. После ошибки резерв возвращается один раз.
Готовая картинка сохраняется независимо от подписи: недоступность текста даёт
нейтральную локальную подпись.

По умолчанию действует существующая пара Polza/Replicate. `IMAGE_PROVIDER`
выбирает основной маршрут, `IMAGE_BACKUP_PROVIDER` — резерв (`none` отключает).
Поддерживаются `polza`, `flux-kontext`, `nano-banana`, `fal`. Для fal нужен
`FAL_KEY`; допустимые `FAL_IMAGE_MODEL`: `fal-ai/flux-pro/kontext` и
`fal-ai/nano-banana/edit`. Наличие ключа не подтверждает оплату и качество.
После ошибок используется временная пауза поставщика. В админке, вкладка
«Деньги», показаны состояние маршрутов, очередь, лимиты и сведения о копиях.

Лимиты по умолчанию: 50 обычных работ на пользователя за 24 часа,
200 попыток изображения на сервис за 24 часа; для пилота улыбки — 100
генераций на сервис за сутки. Настройки: `JOBS_PER_USER_PER_DAY`,
`AI_MAX_ATTEMPTS_PER_DAY`, `SMILE_GENERATIONS_PER_DAY`.

Пилот улыбки по умолчанию использует Polza. Для переключения новых примерок
на fal необходимы `FAL_KEY`, `SMILE_PROVIDER=fal` и
`SMILE_EXTERNAL_PROVIDER_APPROVED=fal`. Последний флаг включают после проверки
условий обработчика и согласий. Интерфейс показывает получателя; устаревшее
согласие на другого получателя отклоняется. Задача закреплена за своим
поставщиком: переключение не переносит туда уже отправленную фотографию.
На fal отправляются только PNG-кроп рта и маска, полное фото не отправляется.
Указаны отключение истории payload и срок файлов один час; это не гарантия
отсутствия логов у разработчика модели. [Документация fal](https://fal.ai/docs/documentation/model-apis/media-expiration).

Все бакеты `photos`, `brand`, `results` приватные. Обычные результаты выдаются
через проверку владельца по временным ссылкам на час; пилот дополнительно
использует AES-GCM. Ранее сохранённые получателями копии отозвать невозможно.
Шифрование не подтверждает соответствие 152-ФЗ: рабочая инфраструктура пока
в `eu-west-1`. Перенос в РФ, договоры и юридическая проверка требуют отдельного
решения оператора. Подключение нового AI не устраняет этот вопрос.

## Резервные копии

```powershell
npm install --prefix tools/backup-validator --ignore-scripts
.\scripts\run-backup.ps1
.\scripts\install-backup-task.ps1
```

Данные снимаются одним согласованным SQL-снимком через авторизованный Supabase
CLI. Файлы копируются инкрементально. До записи на диск применяется Windows
DPAPI CurrentUser. Папка: `~/Desktop/labframe-backups/encrypted-v2`.
Фото пилота с 24-часовым сроком не архивируются. Проверка:

```powershell
.\scripts\verify-backup.ps1 -IncludeStorage
```

Валидатор восстанавливает типы, строки и ограничения в изолированной PostgreSQL
в памяти; содержимое записей не печатается. Проверка данных не равна запуску
всего приложения на новом сервере. Архив файлов проверяется расшифровкой и
сверкой размера. Метаданные успешной проверки записываются в `backup_runs`.
Почасовая задача работает, когда владелец вошёл в Windows и компьютер доступен;
она не обеспечивает независимый серверный RPO при выключенном компьютере.
Нужны отдельно настроенные переносимый ключ и независимая площадка: текущие
DPAPI-копии требуют исходного профиля Windows. Секрет шифрования пилота,
секреты сервисов и восстановление инфраструктуры проверяются отдельно.

## Проверки и публикация

`npm run build --prefix app`, серверные Deno-тесты и SQL-тесты транзакций
проверяются в GitHub Actions. Секреты AI и реальные фотографии CI не нужны.
Инструкции публикации прежние: main → Vercel; Supabase Functions публикуются
отдельно с `--no-verify-jwt`, поскольку внутри проверяется Telegram initData.
Перед повторным применением миграций сверять журнал. Старые 0018–0030 были
сопоставлены с рабочими функциями/объектами и зарегистрированы без повторного
исполнения финансовых изменений.

Оставшийся WARN `pg_net` в public относится к непереносимому расширению
(`extrelocatable=false`). Переустановка может затронуть очередь HTTP и cron;
без отдельной проверки восстановления расширение не удалять. Таблицы и RPC
для клиентских ролей закрыты; INFO об RLS без политик здесь ожидаемы.

После Vite 8 проверен реальный собранный MobileSAM Worker на двух публичных
снимках, четыре сценария маски. Это не подтверждение клинической точности или
работы Telegram на телефоне. Перед расширением пилота нужны iOS/Android и
согласованный набор стоматологической разметки; маска требует подтверждения.
