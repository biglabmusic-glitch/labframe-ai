# «Примерить улыбку»: закрытый пилот

Доступ есть у администраторов и пользователей с `users.smile_tester=true`.
Заблокированный аккаунт не проходит серверную проверку. Администратор выдаёт
и отзывает доступ в карточке пользователя; знакомому сначала нужно открыть бот.
Тестовый доступ не даёт прав администратора. Генерации пилота ограничены
20 запусками в час на участника, основной баланс генераций не списывается.

## Фотографии и внешняя обработка

- Браузер нормализует фото в PNG без исходных EXIF и шифрует исходник и маску
  AES-256-GCM до загрузки. В приватный `photos` уходят файлы `.enc`.
- Ключ задания выводится через HKDF из отдельного `SMILE_ENCRYPTION_KEY`
  (Functions Secrets), Telegram ID владельца и UUID задания. Ключ привязан
  к заданию, а AEAD — дополнительно к назначению файла. Главный ключ клиенту
  не выдаётся. Не менять его без плана удаления/миграции существующих файлов.
- Сервер расшифровывает изображения в памяти. Polza получает только фрагмент
  вокруг ручной маски и маску, дополненные чёрными полями до 16:9. URL полного
  портрета не передаётся. Разрозненная/чрезмерная маска отклоняется.
- Ручной crop уменьшает раскрываемую область, но не гарантирует обезличивание.
  Внешняя модель видит фрагмент в открытом виде. У Polza собственные сроки
  хранения результатов (в документации — 7 дней); удаление LabFrame их не удаляет.
- Сервер вклеивает изменение только в hard mask. Остальные RGBA исходника
  сохраняются точно. Итог тоже шифруется; браузер получает временную ссылку
  на шифртекст и расшифровывает его в память. Сохранить PNG можно явно.
- Фото, ключи и результаты не добавляются в общую ленту, Telegram-рассылку
  или localStorage. В sessionStorage хранится только ID текущей примерки.

Это закрытый технический пилот для тестовых фото с необходимым разрешением.
База и Storage остаются в существующем регионе Supabase `eu-west-1`.
Шифрование и crop сами по себе не подтверждают соответствие 152-ФЗ и не
заменяют российское размещение, правовые основания и проверку договоров.
Перед использованием реальных пациентских данных требуется решить эти вопросы.

## Удаление и срок доступа

Задание недоступно через API после 24 часов. Ежечасный cron
`smile-private-cleanup` вызывает внутреннюю `smile-cleanup`, удаляющую
через Storage API файлы пилота старше 24 часов (следующая уборка — до часа
позже при исправном cron). Ошибки/задержки уборки требуют контроля.

Кнопка удаления удаляет исходник, маску, итог и manifest. Во время активной
генерации возвращается 409. Маленький `running.json` сохраняется до уборки,
чтобы запоздалый запуск не восстановил задание. Ранее выданные signed upload
URL могут ещё принять зашифрованные файлы; такие сироты убираются тем же cron.
Скачанные пользователем PNG и данные у AI-провайдера этим не удаляются.

## Выпуск и проверки

Порядок публикации остаётся в README/CLAUDE/DEPLOY. Пилот добавляет две
миграции: `smile_testers`, `smile_private_cleanup`; четыре функции:
`smile-preview`, `smile-cleanup`, обновлённые `me`, `admin`.
Старые миграции повторно не применялись. Новые версии локальных файлов
синхронизированы с записанными версиями журнала Supabase.

Проверки:

```powershell
npm run build --prefix app
node scripts/test-smile-crypto.mjs
deno test --allow-all supabase/functions/_shared/smile-crypto_test.ts
deno test --allow-all supabase/functions/_shared/smile-preview_test.ts
deno test --allow-all supabase/functions/smile-preview/index_test.ts
```

Интеграционный тест использует настоящую проверку Telegram HMAC на фиктивном
токене и фиктивные Storage/AI. Он проверяет весь криптографический обмен,
права, владельца, crop, защищённые пиксели и гонку удаления. Платный вызов
реального AI этим тестом не проверяется.

Справка провайдера: https://github.com/polza-ai/docs/blob/main/api-reference/media/create.mdx
